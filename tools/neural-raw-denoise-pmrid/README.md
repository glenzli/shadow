# PMRID public neural RAW checkpoint adapter

This development tool audits and converts the public PMRID PyTorch checkpoint
without copying upstream source code, weights, or datasets into Shadow.

PMRID is the ECCV 2020 project “Practical Deep Raw Image Denoising on Mobile
Devices”. The pinned upstream repository is Apache-2.0:

- repository: <https://github.com/MegEngine/PMRID>
- revision: `8ebb9e8e96559881dee957f34243933c5beb77dd`
- `models/net_torch.py` SHA-256:
  `56290ec2bc430c58c16345bcac4ed14381b8f059fc1fe66428438bb0bb328970`
- `models/torch_pretrained.ckp` SHA-256:
  `9361614f3514d27351d81909f2215c0fdc38619c0288d936b7266485ac106c14`
- `LICENSE` SHA-256:
  `c71d239df91726fc519c6eb72d318ec65820627232b2f796219e87dcf35d0ab4`

The adapter verifies those files before executing the upstream network
definition. It loads the checkpoint with PyTorch's `weights_only=True` mode.
Generated Core ML packages, compiled models, reports, downloaded datasets, and
upstream checkouts must remain outside the Shadow worktree.

## What is adapted

The published PMRID inference path maps Reno 10x inputs at an arbitrary ISO to
the model's ISO 1600 anchor noise distribution before running the four-channel
residual network. For a normalized Poisson-Gaussian model

```text
Var(x) = shot * x + read_variance
```

the same affine mapping can be derived from Shadow's calibrated per-CFA noise:

```text
scale  = anchor_shot / shot
offset = (scale² * read_variance - anchor_read_variance) / anchor_shot
```

The tool wraps the public network with Shadow's existing Core ML feature
contract:

```text
mosaic           float32 [1, 4, edge, edge]  R/Gr/Gb/B
noise            float32 [1, 8]              read stddev[4], shot slope[4]
denoised_mosaic  float32 [1, 4, edge, edge]
```

For noise values generated by PMRID's own ISO polynomials, the two
preprocessing formulations must agree numerically.

## Reproduce the conversion smoke

Clone the exact public revision outside the repository:

```sh
git clone https://github.com/MegEngine/PMRID.git /private/tmp/shadow-pmrid-upstream
git -C /private/tmp/shadow-pmrid-upstream checkout \
  8ebb9e8e96559881dee957f34243933c5beb77dd
```

Use the same pinned Python dependencies as Shadow's synthetic baseline:

```sh
/opt/homebrew/bin/python3.12 -m venv /private/tmp/shadow-pmrid-venv
/private/tmp/shadow-pmrid-venv/bin/pip install \
  -r tools/neural-raw-denoise-pmrid/requirements.lock
```

Then write all generated payloads to a new external directory:

```sh
/private/tmp/shadow-pmrid-venv/bin/python \
  tools/neural-raw-denoise-pmrid/pmrid.py \
  --upstream-dir /private/tmp/shadow-pmrid-upstream \
  --output-dir /private/tmp/shadow-pmrid-conversion \
  --tile-edge 64
```

Run the focused contracts with:

```sh
cd tools/neural-raw-denoise-pmrid
/private/tmp/shadow-pmrid-venv/bin/python -m unittest -v
```

Set `SHADOW_TEST_PMRID_UPSTREAM` to the pinned checkout to include the external
checkpoint loading contract.

## Deliberate limitations

This conversion is an intake and compatibility experiment, not a product
model:

- the public PMRID benchmark dataset is not downloaded or evaluated by this
  checkpoint;
- the weights are trained for the Reno 10x camera domain;
- the network's architectural receptive field is 965 packed pixels, requiring
  a 482-pixel halo for exact arbitrary tiling;
- the conversion smoke proves fixed-tile Torch/Core ML parity, not seam-free
  full-frame Shadow execution;
- no model or upstream asset is bundled, automatically downloaded, selected by
  default, or exposed in the UI.

The next gate is to evaluate the public checkpoint on the official PMRID
noisy/clean benchmark, then decide whether an overlap-tolerant execution policy,
fine-tuning, or a smaller public architecture is appropriate.
